# TGS 플레이어·봇 스폰 위치 충돌 보완 — 2026-10-11

[변경 기록](../CHANGELOG.md) · [현재 설정](../CURRENT.md) · [버그](../BUGS.md)

## 대상과 확인한 경로

사용자가 TGS에서 봇과 함께 스폰되는 경우를 보고했다. TGS 편집본에는 플레이어 부활, 라운드 시작, 늦은 참가, 봇 생성, CharacterAdded 후 재배치가 서로 다른 선택 코드를 사용하고 있었다.

일부 경로는 캐릭터 로드 전에 위치를 정하고, 비동기 로드가 끝난 뒤 그 위치로 다시 옮겼다. 그 사이 봇이 같은 자리를 선택할 수 있으며, 나중 재배치가 앞선 선택을 덮어쓸 수 있다. 봇의 시작 대기도 현재 라운드 배치 완료가 아닌 Humanoid 존재만 검사했다. 사용자가 겪은 온라인 순간 자체를 녹화·재현한 것은 아니며, 코드에서 확인한 경쟁 경로를 수정했다.

## 변경

- TGS에 서버 전용 TgsSpawnService를 추가. 플레이어와 봇이 같은 예약 정보를 사용한다.
- 플레이어는 캐릭터를 만들기 전에 위치를 예약하고 일시적으로 RespawnLocation에 연결한다. 로드가 끝난 뒤 실제 점유 상태를 다시 확인하고 최종 배치한다.
- 사망 부활·라운드 시작·늦은 참가의 별도 PivotTo를 제거하고 FixedAvatarBody.Load로 통일했다.
- SpawnDistributor는 공통 로더 밖에서 생성된 캐릭터에만 사용하는 보조 경로다. 이미 배치된 캐릭터와 교체된 옛 캐릭터를 다시 이동시키지 않는다.
- 동시에 들어온 동일 플레이어의 Load 요청은 진행 중인 하나의 결과를 공유한다.
- 봇은 예약 중인 위치와 살아 있는 참가자를 피한다. 라운드 배치 준비 중에는 새 봇 충원을 기다린다.
- 이전 캐릭터의 사망 예약은 캐릭터 교체 때 무효화한다. 사망 번호를 별도로 증가시켜 새 사망과 옛 타이머의 번호가 충돌하지 않게 했다.
- 늦은 참가 경로는 로드 실패에도 진행 중 표시를 정리한다. 실패 메시지를 서버에 남긴다.

## 설정

| 항목 | 값 |
|---|---|
| 대상 지점 | Workspace 하위의 Enabled=true SpawnLocation |
| 최소 분리 거리 | 배치 위치와 다른 살아 있는 참가자/봇 사이 12 studs |
| 보류 중 예약 | 다른 플레이어·봇이 동일 지점 선택 불가 |
| 배치 직후 보호 | 1초간 해당 지점 예약 유지 |
| 최근 사용 선호도 | 3초 내 사용한 지점은 점수30 감점; 안전 거리 통과 지점 중 먼 곳 우선 |
| 빈 지점이 없는 경우 | 겹치는 지점으로 강제 배치하지 않음 |
| 플레이어 대기 | 생성 전 예약 최대8초, 생성 후 최종 배치 재시도 최대5초 |
| 봇 재시도 | 기존 봇의 부활은 자리 확보 실패 시0.5초 뒤 재시도; 최초 충원은 기존 충원 루프 이용 |
| 보존 | 스폰 방향, 봇 점수, 사망 후 최소2초/자동10초 부활 |

적용 소스: ServerScriptService의 TgsSpawnService(신규), FixedAvatarBody, SpawnDistributor, DeathRespawnSystem, CapturePointSystem, BotManager. 테니스·로비는 변경하지 않았다.

## 검증

- 기존5개 소스의 Studio 백업과 읽어 둔 원본이 일치하고, FixedAvatarBody.Reference 보존 확인.
- 최종6개 소스 Luau 컴파일 통과. Play 종료 후 임시 검사 Script가 편집본에 남지 않음을 확인.
- 정상 서버 Script에서 분리/실제 생성 검사26개 통과. 4개 동시 예약의 유일성, 5번째 예약 거절, 해제 후 재사용, 최종 점유 재검사, 중복 배치 방지, 비활성 지점 제외, 모든 지점 점유 시 강제 배치 거절, 사망 몸체 제외, 1초 보호와 만료, 옛 캐릭터 거절을 확인.
- 실제 TGS 플레이어에 Load를 동시에2회 호출하여 CharacterAdded가1회이고 두 호출이 동일 캐릭터를 받는 것을 확인. 배치/로딩 플래그 및 RespawnLocation 복원 확인.
- 실제 TGS Play 부활 검사8개 통과. 플레이어와 봇 동시 사망 후 자동 부활, 봇 점수 보존, 반복 부활의 분리를 확인.
- 살아 있는 봇을 고정한 검사에서 플레이어 최종 부활 위치와 가장 가까운 봇 사이 약180.07 studs. 이는 해당 검사 결과이며 매번180 studs를 보장하는 설정은 아니다.
- 옛 사망 예약이 남은 상태에서 캐릭터를 교체하고 새 캐릭터도 사망시켰을 때, 옛10초 타이머에는 부활하지 않고 새 사망의 타이머로 부활하는 것을 확인.
- 총34개 검사 통과. 실제 온라인 여러 계정의 동시 입장/부활, 사용자 환경의 원래 증상 개선 여부는 별도 확인이 필요하다.
- 콘솔에는 기존 맵 장식 스크립트의 asset require 권한 및 GuiFolder/Handle 대기 경고가 있었으며 이번 변경의 해결 범위에 포함하지 않았다.

## 복구와 게시

수정 전 기존5개 소스와 FixedAvatarBody의 Reference 자식을 Studio ServerStorage.TgsSpawnReservationBackup_20261011에 복제했다. 로컬에도 기존/최종 소스, 테스트, 전체 복구 명령을 보관했다.

복구는 Play를 멈춘 TGS 편집 모드에서 기존5개 소스를 백업으로 복원하고 신규 TgsSpawnService를 제거한다. 백업의 비활성 Script를 실행 영역으로 그대로 옮기는 방식은 사용하지 않는다. 게임 소스·원시 로그·개인 경로·플레이스 백업은 이 공개 문서 저장소에 올리지 않았다.

Studio 적용과 실제 서비스 배포는 별개다. Roblox 게시는 사용자 진행이며 이번 작업에서 게시하지 않았다.
