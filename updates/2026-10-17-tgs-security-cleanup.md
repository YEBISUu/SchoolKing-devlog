# 2026-10-17 — TGS 백도어 로더 제거

## 결과

사용자의 제거 승인 후 TGS 크라운 Studio 편집본에서 외부 코드 로더를 담은 **최상위 묶음 47개**를 제거했다. 중첩 항목을 포함하면 실행 Script 50개와 ModuleScript 76개이며, NumberPose·호출 경로용 제약 객체를 합쳐 제거한 객체는 200개다.

앞서 전달받은 다른 작업자의 “46개”는 당시 보고다. 이번 수치는 현재 연결된 TGS의 실제 트리를 다시 검사한 결과이며, 같은 경로 이름이 반복되어도 객체별로 구분했다.

정상 소스 1,913개는 원문 그대로이며 모델 부품 22,168개의 검사 속성도 변경되지 않았다. 게임 플레이 코드를 수정하지 않았다. 실제 플레이에서 모든 기능이 동일하게 동작한다는 검증까지 수행한 것은 아니다.

## 제거 판단

- 조명 설정처럼 보이는 코드에서 에셋 설명을 변환한 숫자나 하위 Pose 값을 외부 모듈 호출에 사용했다.
- EffectBuilder 계열은 설명 문자열로 실행 대상을 계산하는 로더였으며, 같은 구조가 다른 이름의 스크립트 안에도 들어 있었다.
- PoseTexture/TextureConfiguration과 ObjectTextureService/PoseLink 등에서 데이터 객체를 통한 외부 모듈 로딩 경로를 확인했다.
- 대상 위치에서 코드가 처리하도록 작성된 `LightPart`는 0개였다. 대상 밖 스크립트에서 확인한 주요 대상 이름에 대한 코드 참조도 검색되지 않았다.
- 이름만으로 삭제하지 않고 해당 소스와 하위 모듈을 검토한 뒤, 객체 ID·경로·소스·하위 구성 일치 여부를 재확인하고 제거했다.
- 외부 모듈을 실제로 불러오거나 의심 스크립트를 실행하지 않았다. 모듈의 최종 내용과 과거 실행 성공 여부는 조사 범위 밖이다.

## 책 뷰모델

`ReplicatedStorage.Viewmodels.Book_Viewmodel`과 `ServerStorage.ViewmodelSources.Book_Viewmodel` 양쪽의 로더를 제거했다.

두 모델 모두 기존 부품 10개를 유지하며 남은 스크립트는 0개다. 회복 아이템 처리 코드를 포함한 다른 소스는 변경하지 않았다.

## 백업과 적용

- 제거 전 로컬 outputs에 소스·객체 구조·위치·속성 자료를 저장하고 파일을 다시 읽어 구성을 검증했다.
- Studio의 `ServerStorage.TGSBackdoorQuarantine_20261017`에 격리 백업을 만들었다.
- Script/ModuleScript는 Folder로 바꾸고 원문은 StringValue에 보관했다. 이 백업에서 실행 가능한 소스 컨테이너는 0개다.
- Studio 백업의 원문 126개를 로컬 원본과 정확히 비교한 후 제거했다.
- 제거 전에 현재 대상 소스와 백업이 같은지, 새 하위 항목이 끼어들지 않았는지, 정상 영역이 바뀌지 않았는지 검사했다.
- 복구용 대상 자료와 검증 결과는 보존했다. 검증에만 쓰인 전체 맵 임시 기준 데이터는 작업 후 지워 불필요한 데이터 증가를 줄였다.
- 백업에는 악성 의심 원문이 포함되므로 전체를 자동 복원하거나 실행하지 않는다. 기능 문제가 발견되면 필요한 정상 부분만 검토하여 복구한다.

## 실제 수행한 검증

| 항목 | 결과 |
|---|---|
| 원래 소스 컨테이너 | 2,039개 |
| 제거 | Script 50개 + ModuleScript 76개 |
| 제거 후 소스 컨테이너 | 1,913개 |
| 서로 다른 소스 문자열 | 622개 → 602개 |
| 정상 소스 원문 대조 | 1,913개 일치 |
| 정상 영역 구조·검사 속성·속성값 대조 | 예기치 않은 변경/추가 0개 |
| BasePart 위치·크기·충돌·재질 등 검사 | 22,168개 유지 |
| 제거 대상 잔존 | 0개 |
| 조사한 로더 식별 문자열 재검색 | 0건 |
| 격리 백업 내 실행 가능한 스크립트 | 0개 |
| 책 뷰모델 두 곳 | 각 부품 10개 유지, 스크립트 0개 |

최초 정상 영역 기준에는 Studio 내부 ScriptDebugger도 포함돼 있었다. 스크립트 제거에 따라 디버거 객체 126개가 자동으로 사라졌으며, 제거한 소스의 이름별 수량과 일치함을 확인했다. 이를 게임 모델 손실로 처리하거나 숨기지 않고 별도 분류했다. 그 밖의 72,495개 비대상 객체에는 검사한 구조·속성 변화가 없었다.

## 범위와 남은 확인

- TGS Studio Edit에 적용했다. Roblox 게시는 하지 않았다.
- 이번 작업에서 Play·실제 온라인 다인전·게임 재접속 테스트는 하지 않았다.
- 무기 발사/재장전, 회복 책, 점프대, 그래플, 경기 종료/로비 이동은 게시 전후 실제 플레이로 최종 확인해야 한다.
- 설치 플러그인·계정 접근·삽입자·이미 실행 중인 서버·게시 버전의 안전성을 보증하지 않는다.
- 로비와 테니스는 이번 제거 작업에서 변경하지 않았다. 테니스의 선행 검사 기록은 [별도 문서](2026-10-17-tennis-security-audit.md)에 있다.
- 기존 감염 백업이나 모델을 다시 가져오면 로더가 재유입될 수 있으므로 복구·재수입 때 검사가 필요하다.
- 게임 소스, 원시 로그, 플레이스 백업, 개인 경로 및 모듈 포인터 목록은 공개 문서에 포함하지 않았다.
