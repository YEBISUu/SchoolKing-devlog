# 2026-10-11 스나이퍼 반동 복귀 및 배율 기억

[현재 설정](../CURRENT.md) · [이전 조사](2026-10-11-sniper-recoil-research.md)

## 적용 범위와 동작

TGS·테니스 Studio 편집본에 적용했다. Roblox 게시는 하지 않았다.

기존 수직 반동은 시선에 계속 누적됐다. 이번에는 스나이퍼의 수직 반동을 플레이어의 기본 조준 각도와 분리하여, 빠르게 올라갔다가 원래 조준 방향으로 부드럽게 내려오는 일시적인 카메라 각도로 처리한다. 다른 총은 기존 누적 방식과 수평 반동 계산을 유지한다.

처음 스코프에 들어가면1배로 시작한다. 휠로 바꾼 마지막 배율은 같은 플레이어 접속 내에서 기억하여, 스코프를 다시 켜거나 스나이퍼 Tool이 재생성돼도 사용한다. 플레이어 로컬 속성 SniperScopeZoom에 저장하며, 새 서버/플레이스로 접속할 때까지 이어지는 영구 저장은 아니다. 유효하지 않은 저장값은1배로 처리한다.

## 최종 설정

| 항목 | 값 |
|---|---|
| 수직 반동 | 5.5도 |
| 스코프 조준 반동 배수 | 0.8, 실제 수직4.4도 |
| 수평 반동 | 기존0.45도 |
| 빠른 상승 | 0.06초 |
| 최고점 유지 | 0.04초 |
| 부드러운 복귀 | 0.55초 |
| 전체 동작 | 약0.65초 |
| 첫 배율 / 가변 범위 | 1배 / 1~4배 |
| 조준 입력 | 기존 우클릭 토글, 진입 대기0.15초 |
| 배율 전환 | 기존 FOV·감도 전환0.35초 |

초기 복귀 구현은 기존2.99도(조준2.392도)로 검사했다. 이후 사용자가 반동을 훨씬 크게 요청하여5.5도(조준4.4도), 약1.84배로 높였다. 복귀 시간은 유지했다. 발사 간격1.2초, 피해·탄 크기·관통·명중 보정·사운드는 이번에 변경하지 않았다.

## 입력 처리

위로 튀는 동작은 빠르게 감속하며 최고점에 도달한다. 복귀는 시작과 끝의 속도가 부드러운 곡선을 사용하며 원래 각도 아래로 튕기지 않는다.

플레이어가 마우스를 아래로 움직이면 현재 보이는 반동부터 상쇄한다. 반동을 모두 상쇄하고 남은 입력은 기본 조준에 적용한다. 따라서 손으로 내린 만큼을 자동 복귀가 다시 내려 버리는 중복을 막는다. 위로 추적하는 입력은 기본 조준에 유지한다.

무기 해제·교체·사망·캐릭터 교체·메뉴/연출·Frozen 상태에서는 남은 임시 반동을 정리한다. 수직 시야 상한에 막힌 보이지 않는 반동도 제거한다. 모바일의 기존 수직0.65배 정책을 유지한다.

## 수정 위치

- ReplicatedStorage.GunSystem.GunConfig: Sniper의 반동 강도·복귀 설정, 최초 AimFOV70.
- ReplicatedStorage.GunSystem.Recoil: 설정이 켜진 무기에만 임시 수직 반동과 입력 상쇄.
- StarterPlayer.StarterPlayerScripts.CustomFPCamera: 기본 조준과 임시 반동을 합쳐 렌더링.
- ReplicatedStorage.GunSystem.SniperScope: 최초1배 및 로컬 마지막 배율 기억.

스나이퍼 ClientHandler는 기존 발사·스코프 연결을 사용한다. 실제 발사 방향 계산 후 카메라 반동이 시작되는 순서를 유지한다.

## 검증

- 두 맵에서 수정 소스4개씩 컴파일 및 적용 상태 대조.
- 양쪽 각각94개 분리 단언 통과. 최종5.5도 설정으로 재실행했다.
- 빠른 상승·최고점·복귀 절반·완전 복귀, 30/60/144 FPS 범위·단조 복귀 검사.
- 아래 입력의 일부/전체/초과 상쇄, 위 방향 추적, 모바일0.65배, 시야 상한에서 잔여 각도 검사.
- 교체·사망·부활·메뉴·기능 끄기 정리 검사.
- 목발·컴퍼스·토스터·실리콘건의8발 시퀀스에서 기존 모듈과 새 모듈의 수직/수평 결과 동일.
- 테니스 Play에서 일반 LocalScript로 스코프·반동 모듈과 실제 CustomFPCamera를 연결하여 검사했다. 경기 진행·연출을 임시 중지한 분리 환경이며, 중지한 스크립트나 시험용 코드는 Edit에 남기지 않는다.
- 첫1배,3배 변경/감도, 해제 시 감도 복원, 재진입·새 스코프 인스턴스에서3배 유지, 잘못된 저장값의1배 복귀를 확인했다.
- 초기 강도에서 테니스 실제 카메라를 1배·4배로 측정: 양쪽 최고2.392도, 0.85초 뒤 잔여0도·아래쪽 초과0도. 당시20개 런타임 확인 항목 통과.
- 강도5.5도 변경 후 양쪽94개 분리 검사를 다시 통과했다. 추가 Play 측정은 입력·다른 카메라 동작을 완전히 배제하지 못해 고정 시선의 최고점/복귀량 검증으로 채택하지 않았다. 최종4.4도 조준 반동의 실제 체감은 사용자 확인 대상이다.
- Play 종료 후 양쪽 Edit의 네 소스가 최종 준비본과 정확히 같고 컴파일되는지, 두 복구 백업이 존재하는지 재확인했다.

실제 사용자 마우스/휠 조작감, 온라인 다인 플레이, 물리 모바일 터치는 미확인이다. 분리 검사 중 캐릭터 교체와 실제 라운드·부활 플레이는 구분한다. 기존 맵 HealthScript/RobloxTeam 및 애셋 권한 오류는 별도 항목이며 이번 작업의 해결 범위가 아니다.

## 복구

수정 전 네 소스는 양쪽 ServerStorage.SniperScopeRecoveryBackup_20261011 및 로컬 outputs에 보관했다. 해당 폴더의 RollbackCommand에는 Play를 중지한 Edit에서 네 소스를 되돌리는 명령이 있다. 이번 작업에서 전체 복구 명령을 실제 실행하지는 않았다.

강도 추가 조정 직전 GunConfig는 ServerStorage.SniperRecoilStrengthBackup_20261011에 별도 보관했다. 이 백업은 부드러운 복귀/배율 기억은 적용하고, 반동 강도만 이전2.99도로 돌릴 때 사용할 수 있다.

복귀 방식만 끄려면 GunConfig.Sniper.RecoilRecoveryEnabled=false로 바꾸고 새 Play 세션에서 확인한다. 이 경우 강도5.5도는 유지되므로 원래 강도까지 원하면 RecoilVertical도2.99도로 복구한다. 스코프 배율 기억은 별도 기능으로 유지된다.

공개 저장소에는 이 개발 문서만 올린다. 게임 소스·원시 로그·플레이스 백업은 공개하지 않는다.
