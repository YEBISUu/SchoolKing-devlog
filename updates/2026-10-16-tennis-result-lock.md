# 테니스 결과 연출 중 HUD·전투 입력 차단
날짜: 2026-10-16

[이전 조사](2026-10-16-tennis-cinematic-ui-investigation.md) · [현재 설정](../CURRENT.md)

## 문제와 적용 결과

결과 상태가 시작된 뒤 카메라 전환까지 3초 동안 전투 HUD와 무기 입력이 남아 있었다. 이후에도 중앙 탄약 UI의 매 프레임 갱신이 연출의 숨김 처리를 덮어썼다. 조사 당시 목발의 로컬 탄약 감소는 재현했지만 서버 탄약은 유지됐다.

테니스 편집본에 결과 상태 공통 조건을 적용했다. RoundOver/MatchOver 진입 즉시 전투 HUD를 숨기고 무기를 해제하며, 결과 카메라·미리보기 중에도 차단을 유지한다. 다음 Active 상태와 카메라 복귀 후 표시와 입력을 복구한다. 카메라 대기 3초, 라운드 결과 6.5초 및 기존 처치 슬로모션 설정은 유지한다.

적용 대상은 테니스뿐이다. 기존 15개 소스를 수정하고 공통 모듈/클라이언트 3개를 추가했다. TGS·로비는 변경하지 않았다. Roblox 게시는 수행하지 않았으며 사용자가 진행한다.

## 구현 범위

| 영역 | 최종 동작 |
|---|---|
| 공통 상태 | TennisCombatGate: Phase가 Active이고 DuelActive=true이며 결과 카메라/미리보기가 아닐 때 전투 허용 |
| 총기 | 목발·컴퍼스·토스터·실리콘건·스나이퍼의 발사 진입과 각 발 처리, 조준 시작, 재장전 및 관련 요청 차단. 이미 누르고 있던 연사도 각 발 검사 |
| 장비 | 결과 전환 시 서버/클라이언트에서 장착 해제. 비전투 중 다시 장착되는 Tool도 해제 |
| 투척·근접 | 컵·캔의 준비/발사 및 지연 릴리스 차단, 쓰레받이 공격·방어 시작 차단 |
| 회복·그래플 | 진행 중 회복/그래플 정리, 비전투 재시작과 지연된 무기 복귀 차단 |
| 전투 HUD | TennisCombatPresentation이 결과/카메라 상태의 ScreenGui 숨김을 관리. 나중에 생성되거나 다른 코드가 다시 켠 HUD도 숨김 |
| 중앙 탄약·조준점 | GunUIController가 공통 차단 조건을 확인하여 결과 중 다시 켜지 않음 |
| 결과·이동 UI | 결과 창, 연출, 로비 이동/로딩, 관전·미리보기 조작 화면은 유지. 경기 점수판은 결과 중 숨김 |
| 복구 | 숨기기 전 ScreenGui 상태를 보관하고 결과 해제 시 복구. 다음 라운드 정상 HUD 복귀 확인 |
| 물리 | 이번 차단을 위해 캐릭터를 추가로 고정하거나 Frozen을 켜지 않음. 기존 슬로모션의 시간/곡선 변경 없음 |

기존 TennisCinematic의 ScreenGui 숨김/복구 스냅샷은 제거해 두 코드가 서로 상태를 덮어쓰지 않도록 했다. 카메라와 캐릭터 연출은 기존 코드가 계속 담당한다.

## 폭죽 화살표

기존 서버 정리에 더해 FireworkGuideClient를 추가했다. 편집용 태그, 지정 생성자 속성 또는 FireworkPreviewPoints 아래의 EditorDirectionGuide_ 이름으로 식별되는 가이드만 클라이언트에서 제거한다. 최초 인스턴스뿐 아니라 이후 추가되거나 뒤늦게 태그가 붙는 경우에도 적용한다. 일반 Beam과 실제 폭죽은 이 규칙의 대상이 아니다.

편집 모드의 가이드 40개는 보존했다. 원래 보고된 간헐 노출은 조사 당시 재현하지 못했으며, 이번 검증은 알려진 가이드가 런타임에 추가되는 경로를 인위적으로 만든 검사다. 게시본에서 원래 증상이 완전히 사라졌다고 단정하지 않는다.

## 실제 수행한 검증

- 분리 검사 77개 통과: 상태 조합 11개의 입력/HUD 규칙 22개, 실제 다섯 총기의 fireOne 함수에 차단 조건을 주입한 부작용 검사 50개, 일반 Active 진입 검사 5개.
- 새 Studio Play의 일반 라운드 13개 검사 통과: 기존 Fire 입력 경로로 정상 탄약 23→21, 봇 강제 사망으로 결과 전환, 결과 중 재장착/발사 시도에도 로컬 21발 유지, HUD/점수판 숨김, 새 HUD 생성과 외부 Enabled=true 재설정 차단, 연출·이동 UI 유지, 다음 라운드 HUD/입력 복구.
- 결과 진입 약 0.022초 첫 표본부터 6.4초까지 26회 관찰에서 HUD/중앙 탄약/점수판 숨김과 입력 차단 유지. 카메라는 약 3.09초 표본부터 연출 상태였다. 캐릭터는 추가 고정되지 않았다.
- 클라이언트 가이드 6개 검사 통과: 초기 잔여 0개, 이름/생성자/초기 태그/뒤늦은 태그 경로 제거 및 무관한 Beam 보존.
- 최종 결과 창: 클라이언트에 MatchOver와 결과 경과 시간을 주입해 결과 패널·로비 이동 UI 유지, 전투 HUD 숨김, 입력 차단, 원래 Active 복구를 확인했다. 실제 최종 점수 도달과 서버 이동의 전체 검증은 아니다.
- Play 종료 후 수정/추가한 18개 소스의 컴파일·체크섬/길이 대조, 수정 전 백업 17개 대조, 편집 가이드 40개 보존 확인.

## 미확인·별도 항목

- 일반 라운드 테스트는 Studio 단일 클라이언트와 기존 입력 BindableEvent를 사용했다. 실제 마우스/모바일 조작, 온라인 다인전, 관전자, 스코프·투척·회복·그래플을 누른 채 결과로 넘어가는 전체 조합은 추가 확인이 필요하다.
- 봇 체력을 직접 0으로 만든 결과 전환 검사이므로 실제 명중 처치의 슬로모션 체감 전체를 검증한 것은 아니다.
- Studio 출력에 이번 수정 대상 밖의 Workspace 모델 스크립트 오류, Roblox UI 경고 및 에셋 권한 경고가 남아 있었다. 프로젝트 전체 무오류로 보고하지 않는다.
- 실제 게시/서버 텔레포트는 수행하지 않았다.

## 백업과 복구

수정 전에 ServerStorage.TennisResultLockBackup_20261016과 로컬 outputs에 원본 17개를 보관했다. 복구 스크립트는 Edit 모드에서 원래 소스를 되돌리고 새 모듈/클라이언트 3개를 제거한다. 백업 폴더는 남긴다.

공개 저장소에는 이 개발 문서만 기록한다. 원본/수정 게임 소스, 실행용 복구 스크립트, 테스트 코드, 원시 진단 자료는 로컬에 보관한다.
