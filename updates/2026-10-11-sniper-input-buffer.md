# 2026-10-11 — 스나이퍼 재장전·줌 입력 누락 보완

[현재 설정](../CURRENT.md) · [버그 기록](../BUGS.md)

## 확인한 문제

사용자는 재장전 버튼을 여러 번 눌러도 바로 반응하지 않는 경우와 그래플로 공중에 올라간 뒤 줌이 바로 켜지지 않는 경우를 보고했다. 발생 시점을 모두 특정하지는 못했다. 검사 당시 테니스에서 사용 중인 무기는 스나이퍼였으며, 관련 소스는 TGS와 같았다.

1. 장착 중 스나이퍼의 재장전·줌 요청을 즉시 반환하여 버렸다. 그래플에서 총으로 돌아오는 장착 구간에서도 동일했다.
2. 그래플 복귀의 조준 복구는 장착 시간+0.1초 후 우클릭을 **계속 누르는지** 검사했다. 짧게 눌렀다 놓는 스나이퍼 토글 입력과 맞지 않았다.
3. 탄창이 1발일 때 R을0.4초 이상 누르면 강화탄 합치기 입력으로 소비했지만, 합치기는2발 이상에서만 가능했다. 키를 놓아도 일반 재장전으로 돌아가지 않았다.
4. 클라이언트 재장전 상태를 서버의 모든 스나이퍼 응답으로 덮어썼다. 최신 재장전 요청 이전 응답을 구분할 수 없어 경합 가능성이 있었다. 이 경우는 지연 응답 주입 테스트로 보완을 확인했으며, 사용자의 원래 모든 실패 원인을 단정하지 않는다.

## 변경

TGS와 테니스 Studio 편집본에서 아래3개 소스를 수정했다.

- `StarterPack.Sniper.ClientHandler`
- `StarterPack.Sniper.ServerHandler`
- `StarterPlayerScripts.GrappleClient`

스나이퍼는 장착/근접 동작 중 들어온 재장전 요청을1개 기억하고 가능해지면 실행한다. 장착/재장전/근접 동작 중 들어온 줌 토글도 유지하며, 다시 클릭하면 대기 중인 줌을 취소한다. 재장전 중 줌을 요청하면 완료 후 줌에 들어간다.

입력 연결을 뷰모델 준비보다 먼저 수행하고, 장착 세대 번호로 이전 장착의 지연 콜백을 무효화했다. 무기 해제·사망·메뉴 등에서는 대기 입력을 지운다.

그래플을 든 상태에서 우클릭하면 스나이퍼로 복귀할 때 해당 클릭을 전달한다. 마우스를 놓아도 요청이 유지되며 기존 장착이 끝나면 조준한다. 다른 무기의 기존 홀드 조준 경로는 유지했다.

재장전 요청/취소에는 증가하는 요청 번호를 붙이고 서버 응답에 해당 번호와 정확한 Tool을 포함한다. 현재 요청보다 오래된 응답이나 다른 Tool 응답으로 재장전 상태를 덮어쓰지 않는다. 연타해도 재장전을 중복 시작하지 않는다.

탄창이0~1발이라 합치기를 시작할 수 없는 경우 R을 길게 눌러도, 키를 놓으면 일반 재장전을 요청한다. 장착 중 대기하던 합치기 요청은 R을 놓으면 취소된다.

## 유지한 설정

- 장착0.85초, 일반 재장전2.5초, 기본 스코프 진입0.15초 유지.
- 스코프 진입 시간은 입력 시점부터 계산한다. 장착/재장전 대기 중 이미0.15초가 지났다면 준비된 뒤 추가0.15초를 다시 기다리지 않는다.
- R 짧게 누르기와 R0.4초 이상 유지하여 강화탄 합치기 구분 유지. 짧은 R은 키를 놓을 때 일반 재장전 요청.
- 강화탄 합치기3초, 이미 만들어진 강화탄 보유 중 재장전 제한, 사격 간격·피해·탄약 소비 유지.
- 테니스 처치 슬로모션과 라운드 종료 규칙은 수정하지 않았다.

## 검증

양쪽 총6개 소스 컴파일과 최종 소스 일치 확인.

테니스 Studio Play에서 실제 스나이퍼 핸들러와 서버 탄약 처리를 사용하고, 임시 테스트용 BindableFunction을 통해 실제 입력 처리 함수를 호출했다. 그래플의 실제 무기 복귀 함수를 사용했다. 물리 키보드/마우스를 직접 자동 입력하거나 온라인 다인전으로 재현한 테스트는 아니다.

**기본27개 + 추가10개, 총37개 검사 통과.**

- 장착 중 줌/재장전 요청 보존, 장착 잠금 유지, 완료 후 실행.
- 줌 토글 재클릭 취소, 재장전 중 줌 요청 보존, 무기 해제와 메뉴에서 취소.
- 빠른 재장착 때 이전 타이머가 새 장착을 일찍 해제하지 않음.
- 재장전 연타 중복 없음, 이전 상태 응답/다른 Tool 응답 무시.
- 서버 탄약 실제4→5, 예비30→29; 1발 남은 상태에서 긴 R 입력도 일반 재장전 완료.
- 강화탄 대기 취소, 실제 합치기 시작/취소/완료, 완료 후 키를 놓아도 강화탄 보존.
- 그래플 복귀에 짧은 줌 의도 전달. 추가 물리 도약 테스트에서 Freefall 상태인 동안 스코프 진입 확인.

최초 테스트 설치 도구가 일반 Script에서 Source를 읽으려 해 권한 오류를 냈다. 도구 준비 과정을 수정한 뒤 위37개 검사를 수행했다. 이 임시 테스트 코드는 Edit에 저장하지 않았다. 수정된 게임 핸들러에서 새 오류는 관찰하지 않았다.

## 백업과 남은 확인

두 Studio의 `ServerStorage.SniperInputBufferBackup_20261011`에 각3개 원본을 저장했다. 로컬 outputs의 `sniper-input-buffer-20261011`에 원본/최종 소스, 테스트 결과, `rollback.luau`를 보관했다. 공개 저장소에는 개발 문서만 반영한다.

사용자의 실제 키 입력과 전체 그래플 발사→연결→이탈 과정 반복, 실제 모바일, 온라인 두 계정 환경은 추가 확인이 필요하다. 이번 수정 범위는 스나이퍼 입력과 해당 그래플 복귀 경로이며, 다른 총의 재장전 핸들러는 변경하지 않았다.

Roblox 게시는 하지 않았다. 사용자가 게시 후 새 서버에서 확인한다.
