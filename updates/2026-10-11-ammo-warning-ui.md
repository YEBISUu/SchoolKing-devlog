# 탄약 경고 UI와 스나이퍼 강화탄 동기화

[변경 기록](../CHANGELOG.md) · [현재 설정](../CURRENT.md) · [남은 확인](../TODO.md)

2026-10-11. TGS·테니스 Studio 편집본에 적용. Roblox 게시는 진행하지 않았다.

> 후속 변경: 무지개 주기0.8초, 탄 수별 합치기 시간·진행 게이지·완료/발사 음원은 [스나이퍼 합치기 최신 기록](2026-10-11-sniper-compression.md)을 따른다. 아래 2.4초/합치기3초는 이번 경고 UI 작업 당시 값이다.

## 당시 최종 표시

중앙 잔탄 아크와 오른쪽 하단 탄창 숫자가 동일한 색/주기로 바뀐다. 예비 탄약 숫자는 기존 표시를 유지한다.

| 상태 | 표시 |
|---|---|
| 탄창 50% 이상 | 기존 색 |
| 10% 초과, 50% 미만 | 주황 RGB255/154/52, 0.9초 점멸 |
| 10% 이하 또는 마지막 1발 | 빨강 RGB255/64/64, 0.4초 점멸 |
| 스나이퍼 합친 탄 보유 | 무지개색 순환 + 탄창 숫자의 밝은 외곽선 |
| 합친 탄 발사 후 0발 | 일반 빈 탄창 경고/재장전 안내로 복귀 |

마지막 1발은 작은 탄창에서도 빨강이다. 스나이퍼 1/5=20%, 토스터 1/6≈16.7%는 원래 비율 조건만으로 주황이므로 후속 요청에 맞춰 예외를 추가했다. 무지개 상태는 탄창이 남아 있고 서버가 강화탄 보유를 알려줄 때에만 우선한다.

무지개 색은 2.4초에 한 바퀴 순환하고 약한 밝기 변화를 동반한다. 색상 순환은 탄약 수량이나 피해량을 변경하지 않는다.

## 재장전 안내와 편집 위치

`StarterGui.GameHUD.ReloadPrompt`의 TextLabel은 배경 없는 흰 글씨이고, 빨간 `UIStroke`가 **글자 윤곽**을 따라 점멸한다. 사각형 박스/테두리는 없다.

- 기본 Position: X Scale0.5/Offset0, Y Scale0.5/Offset112.
- 크로스헤어 아래 위치는 이 객체의 Position을 직접 수정한다. 컨트롤러는 Position을 덮어쓰지 않는다.
- 일반 위험 잔탄에서 표시하고, 재장전 중·전투 HUD 비활성·무한 탄약·미사용 강화탄 보유 중에는 숨긴다.
- 문구: `R키를 눌러 재장전`.
- `ReplicatedStorage.GunSystem.AmmoWarningStyle` 속성: `LowColor`, `CriticalColor`, `LowBlinkPeriod`, `CriticalBlinkPeriod`, `EmpoweredColorPeriod`.
- 무기 해제/비전투 상태에서는 숫자 색·투명도·외곽선을 원래 값으로 복구한다. 기존 중앙 아크 배치와 스코프 중 HUD 정책을 유지한다.

## 강화탄 발사 후 1발 표시/재장전 차단 보완

사용자 보고: 탄 합치기 후 발사해도 1발이 남은 것으로 표시되고 재장전되지 않음.

- 서버가 승인한 발사는 탄창 소모와 강화 상태 해제를 먼저 동기화한 뒤 효과음·궤적·피해 처리를 진행한다. 후속 처리 오류가 발생해도 소모된 탄약 갱신이 뒤에 남지 않도록 했다.
- 잘못된 발사 원점/벡터 등으로 거절한 발사도 소유자에게 실제 서버 탄약을 다시 보낸다.
- 탄약 패킷에 강화 상태를 포함하고 클라이언트가 이를 사용한다.
- 잔탄이 0이면 이전 강화탄 속성이 남아 있다는 이유로 일반 재장전을 막지 않는다. 아직 쓰지 않은 강화탄을 보유한 경우의 재장전 차단은 유지한다.
- 기존 재장전 요청 번호/Tool 검증 및 입력 버퍼를 유지한다. UI도 다른 무기의 응답을 무시한다.

발사 간격·피해·합치기3초·일반 재장전2.5초는 변경하지 않았다. 보고된 실제 플레이 증상의 최초 원인을 확정한 것은 아니다.

## 수행한 검증과 한계

최종 소스의 서버 처리·클라이언트 처리·UI 함수를 추출한 분리 환경에서 **53개 검사 통과**:

- 50/49/11/10/0% 경계 및 작은 탄창의 마지막1발.
- LegCrutch·Compass·Toaster·SiliconGun·Sniper 각각 일반색/주황/빨강과 중앙/하단 점멸 동기화.
- 흰 글씨 유지, 배경 없음, 글자 윤곽선 점멸, 작성된 Position 보존, 재장전/비전투/무한 탄약 숨김.
- 강화탄 무지개 순환, 재장전 안내 숨김, 소모 후 일반 경고/외곽선 복귀.
- 실제 타이머를 사용하는 합치기 완료 → 강화1발 → 발사0발 → 재장전5발/예비25.
- 오래된 강화 속성이 있어도 빈 탄창 재장전 허용.
- 거절된 발사의 재동기화 및 승인 후 궤적 처리에 의도적으로 오류를 주어도 탄창0/강화해제 패킷이 먼저 반영되는지 확인.

두 맵 각각 최종5개 소스 컴파일/정확한 내용 대조, 안내 속성 및 백업 존재 확인. 임시 검사 객체 제거. 로컬 원본/최종16개 파일도 준비된 소스와 대조했다.

초기에는 실제 플레이 세션에 테스트 탄약 패킷을 보내는 검사를 시도했으나 사용자 조작과 충돌할 수 있어 중단하고 실제 서버값 재동기화를 요청했다. 이 초기 검사는 전체 성공 근거로 사용하지 않는다. 최종53개 검사는 실제 플레이어/리모트 탄약을 변경하지 않는 분리 검사다.

실제 사용자 R 입력·스코프 반복·무기 전환·다인전과 모바일의 최종 체감/화면 검증은 남아 있다. 분리 검사를 온라인 경기 검증으로 표현하지 않는다.

## 적용 및 복구

양쪽 맵의 `GunUIController`, `HUDController`, 스나이퍼 `ClientHandler`/`ServerHandler`를 수정했고 `AmmoWarningStyle` 모듈과 `ReloadPrompt`를 추가했다.

변경 전4개 스크립트는 각 Studio `ServerStorage.AmmoWarningBackup_20261011`과 로컬 작업 산출물에 보관했다. 전체 복구 스크립트는 원본4개를 복원하고 새 모듈/안내를 제거한다. 이번 최종 수정 이후 전체 복구를 실제 실행하지는 않았다.

공개 저장소에는 개발 문서만 반영한다. 게임 소스·원시 로그·플레이스 백업은 포함하지 않는다.
