# 테니스 통합 모드 다시하기 수정
날짜: 2026-10-16

[선행 조사](2026-10-16-tennis-rematch-investigation.md) · [현재 설정](../CURRENT.md)

## 변경 결과

통합 테니스에서 결과 창은 다시 준비 버튼을 표시하지만 서버가 요청을 거절하고 종료 약 11초 후 자동 복귀하던 문제를 수정했다.

- 봇전: 사람 참가자가 다시하기를 누르면 새 경기 시작.
- PvP: 현재 두 참가자가 모두 다시 준비에 동의하면 새 경기 시작. 한 사람의 반복 요청은 두 번째 동의로 계산하지 않는다.
- 결과 창은 기존처럼 경기 종료 8초 후 열린다. 그 뒤 15초 동안 재경기를 선택할 수 있고, 성립하지 않으면 종료 기준 23초에 로비 복귀를 시작한다.
- 기권 종료는 재경기를 제공하지 않으며 기존 11초 복귀 기준을 유지한다.
- 상대가 나갔거나 참가자 중 누군가 복귀 중이면 재경기를 시작하지 않는다. 관전자·미승인 참가자·이미 복귀가 확정된 경기의 요청도 차단한다.
- 새 경기 진입 시 점수 0:0, 첫 라운드, 준비 상태, 결과 시각/복귀 기한과 통계를 초기화한다. 기존 입장 승인과 참가자 구성을 유지한다.
- 결과 화면에는 본인 준비, 상대 준비/대기, 남은 로비 복귀 시간을 표시한다.

테니스 Studio 편집본의 4개 소스를 수정했다. TGS·로비는 변경하지 않았다. Roblox 게시도 수행하지 않았으며 사용자가 진행한다.

## 자동 복귀와 재경기 간 충돌 방지

TennisDuelService가 새 경기의 Preparing 상태를 캐릭터 로딩 등 비동기 작업보다 먼저 공개한다. ModeTravelServer는 경기 번호와 결과 시작 시각, 예약 세대를 묶어 종료 신호와 주기 확인이 동일한 복귀 예약을 사용하도록 한다.

재경기가 시작되면 이전 예약을 무효화하고 이동 UI의 결과 상태도 playing으로 되돌린다. 이미 실행 대기 중인 콜백도 현재 단계·경기 번호·결과 시각을 다시 검사한다. 다음 경기 종료에는 새 예약을 만든다. 로비 복귀가 먼저 확정됐으면 재경기를 허용하지 않는다.

통합 경기에서 참가자가 나간 경우 기존처럼 Waiting으로 바꿔 새 경기를 재시작하지 않고, 결과 상태를 유지해 로비 복귀를 마무리한다. 독립 모드의 기존 재경기 경로는 유지한다.

## 실제 수행한 검증

### 분리 검사 32개 통과

- 요청·초기화 21개: PvP 한 사람 대기/두 사람 시작, 봇전 한 사람 시작, 중복/비참가자 요청, 너무 이른 요청, 기한 도달, 기권/잘못된 단계, 상대 퇴장/복귀 중, 본인 복귀/관전자/승인 누락, 복귀 확정, 독립 모드 지원, 점수·통계·준비·기한 초기화와 비동기 준비 전 상태 공개.
- 복귀 예약 11개: 종료 신호/주기 확인 중복 방지, 절대 기한, 재경기 시 결과 안내 해제, 두 번째/세 번째 경기 재예약, 이전 콜백의 새 결과 침범 차단, 단계 변경 신호가 아직 처리되지 않은 경우의 재검사, 복귀 중복 실행 차단.

실제 수정한 함수 본문을 가져와 모의 환경에서 검사했다. PvP 두 사람은 이 분리 검사에서 확인했으며 실제 두 클라이언트 접속 검증은 아니다.

### 새 Studio Play 두 회

봇 체력을 매 라운드 0으로 만들어 실제 점수/라운드 흐름을 진행했다. 무기 선택 READY는 기존 요청으로 전송했고, 다시하기는 Studio 마우스 입력 도구로 실제 결과 버튼을 클릭했다. 경기 설정·결과 단계·시계를 테스트용 값으로 바꾸지 않았다.

1. 첫 회: 5:0 종료 후 버튼 클릭으로 두 번째 경기 진입. 이전 복귀 기한이 지나도 경기 유지. 두 번째 경기에서 재경기를 선택하지 않은 상태로 종료 약 23.05초에 복귀 시작, Studio returnPreview 수신.
2. 두 번째 회: 각 5:0 종료 후 약 8.62초/8.32초에 버튼을 눌러 두 번 연속 재경기, 총 세 경기 진행. 세 경기 모두 0:0·1라운드로 시작했고 결과 기록 3개 생성.
3. 두 번째 회에서 이전 두 복귀 기한이 지나도 새 경기 유지. 총 15회 Active 관찰에서 GameHUD 활성 확인. 결과→playing 안내가 재경기마다 갱신됐다.
4. 세 번째 경기에서는 선택 시간을 만료시켜 종료 약 23.06초에 복귀 시작, returnPreview 수신을 확인했다.
5. Play 종료 후 수정본 4개 컴파일/정확한 소스 일치, Studio 원본 백업 4개 일치 확인.

첫 회의 추가 클릭 시도는 이미 두 번째 선택 기한이 지난 뒤여서 새로운 요청이 발생하지 않았다. 연속 두 번의 유효 클릭 검증은 두 번째 새 Play에서 수행했다.

## 검증 한계

- 실제 온라인 두 계정 PvP, 파티 복원·관전자·모바일·네트워크 지연과 동시 퇴장 조합은 미확인이다.
- Studio 복귀는 returnPreview까지 확인했다. 실제 Roblox 서버 간 텔레포트 성공을 검증한 것은 아니다.
- 봇 사망을 직접 만들어 종료를 유도했으므로 실제 명중/슬로모션 체감 검증과 구분한다.
- 수정 대상 밖 Workspace 모델 스크립트 오류가 출력에 남아 있었다. 수정한 스크립트의 오류 메시지는 이번 최종 출력 확인에서 발견되지 않았지만 프로젝트 전체 무오류로 보고하지 않는다.

## 복구

변경 전에 ServerStorage.TennisRematchBackup_20261016과 로컬 outputs에 원본 4개를 보관했다. Edit 모드용 복구 스크립트로 해당 4개 소스를 되돌릴 수 있다. 직전 결과 HUD/전투 입력 차단 수정은 그대로 보존하는 백업이다.

게임 소스·복구/테스트 코드·원시 실행 자료는 로컬에만 보관하고, 공개 저장소에는 개발 문서만 반영한다.
