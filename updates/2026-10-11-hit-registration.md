# 2026-10-11 — 되돌릴 수 있는 이동 표적 판정 보정 시험

## 적용과 상태

TEST TGS·테니스 Studio 편집본의 LegCrutch, Compass, SiliconGun, Toaster, Sniper에 적용했다. Roblox 게시하지 않았다. 실제 두 계정의 이동 사격 체감 개선은 미확인이다.

사용자는 중앙에 적을 두고 쏴도 빗나가며 앞질러 조준해야 한다고 보고했고, 실패하면 되돌릴 수 있는 시험 적용을 요청했다. 현재 소스는 발사 요청 도착 시점의 Workspace를 검사하고 있었다. 이 차이가 증상에 기여할 수 있지만, 실전 미스의 유일한 원인으로 확정하지 않는다.

## 동작과 최종 설정

- 클라이언트가 카메라 발사 방향을 구하는 시점의 GetServerTimeNow를 함께 전송한다. 토스터의 기존 shotId 인수는 유지한다.
- 서버 전용 HitRegistrationHistory가 살아 있는 플레이어 캐릭터의 쿼리 가능한 파트 위치·회전·크기를 약 30Hz로 기록한다. 보관 길이 0.35초.
- 발사 시각까지의 지연과 화면 보간 여유 기본 0.05초를 합하되, 총 되감기는 최대 0.2초로 제한한다. 0.05초는 시험 조정값이며 실제 클라이언트 보간 지연을 측정한 값이 아니다.
- 서버 GetNetworkPing의 왕복 지연 절반+0.075초 이내의 발사 시각만 받는다. 이 허용 창도 최대 0.2초. 미래 0.025초 초과, 오래된 값, NaN, 누락된 시각은 기존 현재 위치 판정으로 복귀한다.
- 기록 사이 위치와 회전을 보간한다. 기록 간격 0.12초 초과 또는 인접 기록 이동 20 studs 초과 시 과거 판정을 사용하지 않는다. 사망·캐릭터 교체 시 이전 기록을 버린다.
- ServerStorage의 별도 WorldModel 프록시를 검사한다. 실제 캐릭터를 순간이동시키지 않는다. 벽·지형·NPC는 현재 월드 판정을 유지하고, 더 가까운 장애물이 우선한다.
- NPC/봇은 이번 플레이어 위치 기록 대상이 아니다.
- 기존 피해, 탄약, 산탄 패턴, 탄 크기, 발사 속도 제한은 유지한다. 스나이퍼 중심선 머리 확인과 캐릭터 관통도 같은 과거 위치 검사에 연결한다.
- 과거 위치에서 맞으면 피격 위치·서버 궤적도 해당 판정 위치를 이용한다. 사수의 즉시 표시 궤적과 약간 달라질 수 있다.

## 간단히 끄기 / 전체 원복

ReplicatedStorage.GunSystem 속성:

| 속성 | 현재 값 | 의미 |
|---|---|---|
| LagCompensationEnabled | true | false이면 즉시 기존 현재 Workspace 판정 |
| LagCompensationViewDelay | 0.05 | 화면 보간 여유, 코드에서 0~0.1초 제한 |

편집본에서 false로 바꾸고 새 Play 또는 새 게시 서버로 비교할 수 있다. 실행 중 서버 속성을 바꾸면 해당 세션에서만 적용되며 편집본에는 저장되지 않는다.

수정 전 각 맵 ServerStorage.HitRegistrationBackup_20261011에 무기별 ClientHandler/ServerHandler 원본 10개와 RollbackCommand를 보관했다. 로컬에도 맵별 원본·수정본과 복구 스크립트를 보관했다.

전체 원복은 Play를 중지한 뒤 백업의 RollbackCommand 내용을 Command Bar에서 실행한다. 원본 10개를 복원하고 새 모듈을 제거하며 두 속성을 이전 값으로 되돌린다. 기존 그래플, HUD, 스나이퍼 관통 등 이번 작업 이전 기능은 복구 원본에 포함되어 있다. 이후 같은 무기 스크립트를 추가 수정했다면 전체 원복 전에 그 후속 수정도 별도 보관해야 한다.

## 실제 수행한 검증

- 양쪽 맵 수정 대상 10개 스크립트 및 공통 모듈 Luau 컴파일.
- 양쪽 맵에서 각각 21개 분리 검사: 타임스탬프·상한·비정상 값, 현재 위치 미스/과거 위치 명중, Raycast/Spherecast 벽 우선, 반경 0.1/0.4 구분, 스나이퍼 관통·머리 중심선, 위치 보간·순간이동 시 복귀.
- ServerStorage WorldModel에서 실제 Roblox 충돌 쿼리가 작동함을 확인.
- 양쪽에서 전체 원복을 실제 실행하고 원본 10개 Source의 정확한 일치, 모듈 제거, 이전 속성 복원을 확인한 후 개선안을 다시 적용했다.
- 테니스 실제 서버 Script에서 Heartbeat 기록·과거 명중 결과의 원본 파트 연결·실행 중 끄기 확인.
- TGS 실제 서버 Script에서 맵의 다른 물체를 제외한 대상 분리 검사로 동일 확인. 일반 맵에서 시작한 초기 보조 검사는 대상 명중을 확인하지 못했으므로 최종 PvP 성공 증거로 사용하지 않는다.
- 테스트 실행 후 Play 종료. 임시 테스트 Script/프록시는 편집본에 남기지 않았다.

## 아직 확인하지 않은 항목

실제 두 계정의 좌우 달리기·슬라이딩·그래플 이동·근거리 사격, 0.05초 여유값의 적합성, 높은 지연·낮은 서버 FPS, 여러 플레이어/연사 시 비용, 움직이는 문이나 장애물, 무기별 발사 거절 빈도는 추가 확인이 필요하다. 특히 NPC 사격 체감은 이번 플레이어 위치 보정과 구분한다.

권장 비교는 같은 무기와 거리에서 Enabled true/false를 바꿔 정지 표적·좌우 이동 표적·엄폐물 진입을 비교하는 것이다. 악화되면 우선 false로 끄고, 필요하면 검증된 백업으로 전체 복원한다.

## API 근거

- [Player.GetNetworkPing](https://create.roblox.com/docs/reference/engine/classes/Player#GetNetworkPing): 왕복 네트워크 지연. 처리 시간 전체를 나타내지는 않는다.
- [Workspace.GetServerTimeNow](https://create.roblox.com/docs/reference/engine/classes/Workspace#GetServerTimeNow): 클라이언트의 서버 시각 근사값. 임의 과거 시각을 신뢰하지 않고 서버에서 범위를 제한한다.
