# 테니스 승리 연출 중 UI·발사 및 폭죽 화살표 조사

- 조사일: 2026-10-16.
- 범위: 현재 연결된 테니스 Studio 편집본의 소스·가이드 인스턴스 조사 및 단일 클라이언트 Play.
- 사용자 요청: 조사. 게임 소스/설정 수정과 Roblox 게시는 수행하지 않았다.
- 추가 증상: 하단 HUD·중앙 표시·그 외 UI가 섞여 나오며 총기 발사도 발생한다는 사용자 보고.
- 현재 상태: 중앙 탄약 UI 제어 충돌과 승리 상태의 로컬 발사 재현. 폭죽 화살표의 게임 중 노출은 미재현. 수정 미적용.

## 확인된 결과

### 1. 결과 카메라 전 3초 동안 HUD가 유지됨

`TennisCinematic`은 `RoundOver/MatchOver` 시작 후 `RESULT_CAMERA_DELAY`가 지나기 전에 제목만 표시하고 반환한다. `ownCamera()` 및 HUD 숨김은 3초 뒤에 시작한다.

측정한 RoundOver 두 회에서:
- 0~약 2.8초: GameHUD와 중앙 탄약 UI 활성, 기존 점수판 표시.
- 약 3초 이후: GameHUD 비활성, 기존 점수판 숨김, TennisCinematicCamera=true.
- 결과 동안 DuelActive=false지만 Frozen=false, MenuOpen=false였다. 일반 라운드 종료에서는 다음 준비 단계 전까지 무기를 장착한 채 남을 수 있다.

따라서 “라운드 승리” 제목이 보이는 시작 구간의 하단 HUD는 현재 코드 경로에서 실제 유지된다. 카메라 전환 후 하단 HUD 전체가 다시 표시되는 사례는 이번 두 회에서 확인하지 못했다.

근거: `StarterPlayerScripts.TennisCinematic` 60~89, 112~126행; `ServerScriptService.TennisDuelService`의 celebrateRound/prepare.

### 2. 중앙 탄약 UI의 활성 상태를 두 코드가 반복해서 덮어씀

- Cinematic은 CrosshairAmmoHUD.Enabled=false를 매 프레임 설정한다.
- `GunUIController.layoutIndicator()`는 별도 RenderStepped에서 Enabled를 다시 설정한다.
- 이 표시 조건은 생존/무기/탄약/로비/메뉴/사망카메라/관전/동결을 검사하지만 TennisCinematicCamera와 라운드 종료 상태를 검사하지 않는다.
- 두 재현에서 카메라 연출이 시작된 후 중앙 탄약 UI의 켜짐/꺼짐 전환을 각각 121회, 122회 관측했다. Heartbeat 표본에서는 Enabled=true가 유지되었다.

숨김 목록에는 KillFeed, SpeedBoostHUD 등 일부 별도 전투 UI가 포함되지 않는다. 목록 누락은 소스로 확인했지만, 그 각각의 실제 화면 노출을 모두 재현한 것은 아니다. SniperScope/GrappleHUD 등은 별도 자체 차단 조건도 있어 목록 누락만으로 노출을 단정하지 않는다.

근거: `TennisCinematic` 60~69행, `StarterGui.GunUI.GunUIController` 103~145, 433~436행.

### 3. 승리 연출 중 목발 로컬 발사 처리 재현, 서버 탄약은 유지

결과 시작 약 3.7초 후 기존 MobileInput.Fire 바인딩에 약 0.22초 입력을 전달했다. 이 바인딩은 같은 무기 beginFire 경로를 호출한다. 실제 마우스/터치 조작 검증과는 구분한다.

| 측정 | 결과 |
|---|---|
| 테스트 무기 | LegCrutch |
| 테스트 시 상태 | RoundOver, TennisCinematicCamera=true, DuelActive=false |
| 로컬 탄약 표시 | 23 / 240 → 20 / 240 |
| 발사 뒤 요청한 서버 탄약 응답 | mag=23, reserve=240 |
| 반복 | 동일 로컬 감소 2회, 서버 응답 추가 확인 1회 |

목발 클라이언트 발사 진입점/fireOne에는 라운드 종료·연출 차단이 없다. 서버 승인 전에 로컬 탄약 감소, 발사음 호출, 애니메이션, 총구/탄선 효과를 실행한다. 서버 핸들러는 DuelActive/전투 상태로 거절한다. 이번 확인에서는 서버의 정상 발사로 이어지지 않았고, 실제 피해량 검사는 별도로 수행하지 않았다.

컴퍼스·토스터·실리콘건도 확인한 클라이언트 경로에서 라운드/연출 검사가 없었다. 스나이퍼는 조준 입력에는 연출 차단이 있으나 fireOne은 MenuOpen/DeadCam 등을 확인하고 해당 연출 상태 검사가 빠져 있다. 다른 네 총기의 실제 결과 연출 입력 재현은 아직 수행하지 않았다.

근거: `StarterPack.LegCrutch.ClientHandler` 906~972, 1017~1023, 1261~1277행; 서버 125~143행. 스나이퍼 fireOne 952~1009행.

### 4. 폭죽 화살표는 편집용 가이드이며 게임 중 노출은 미재현

- Workspace.FireworkPreviewPoints 아래 편집용 가이드 40개: Beam 16개와 Attachment 24개.
- 가이드에는 TennisFireworkEditorGuide 태그와 생성자 속성이 있다.
- 활성 FireworkGuideCleanup 서버 스크립트는 기존 태그 및 이후 추가되는 태그 인스턴스를 삭제한다.
- 이번 새 Play의 서버/클라이언트 조사와 결과 구간 관측에서 가이드 수는 0개였다.
- 컨페티 효과 복제 템플릿에는 해당 가이드 Beam이 없었다.
- Workspace.StreamingEnabled=true. 클라이언트 별도 가이드 차단은 없지만, 스트리밍이 이번 증상의 원인이라고 입증되지는 않았다.
- 실제 서비스 게시본과 현재 Studio 소스의 동일 여부 및 사용자가 본 화살표의 정확한 인스턴스는 미확인이다.

현재 편집본의 정상 정리 경로는 확인했으나, 간헐 노출이 해결됐다고 판단하지 않는다. 게시본 차이, 가이드가 나타난 시점/화면, 재생성·복제 경로 등을 추가로 확인해야 한다.

## 제안하는 수정 방향 — 미적용

1. 결과 상태 진입 즉시 전투 입력을 차단한다. 물리 동결과 입력 차단을 분리하여 처치 슬로모션 움직임은 보존한다.
2. 발사 진입과 연사 루프, 지연 발사, 조준·재장전·투척·근접·그래플에 같은 상태 조건을 적용하고 종료 시 누른 입력을 정리한다. 서버의 기존 차단도 유지한다.
3. HUD는 현재 라운드/연출 상태로 표시 여부를 계산한다. 각 UI가 이전 Enabled/Visible 스냅샷을 무조건 복구하거나 연출 중 다시 켜지 않게 한다. 결과/로딩/로드아웃 UI는 단계별로 보존한다.
4. 편집용 화살표는 편집에서 유지하되 실행 시 서버 정리에 더해 클라이언트에서도 초기·후속 추가 가이드를 차단하는 방안을 검토한다. 일반 조명 Beam은 대상으로 삼지 않는다.

## 검증 범위와 한계

- 새 Studio Play에서 봇 체력을 0으로 설정해 라운드 전환을 유도했다. 정상 명중으로 발생한 처치 및 실제 2인 온라인 경기는 아니다.
- 유효 결과 관측 2회: 카메라 전후 UI/속성, 중앙 탄약 활성 충돌, 목발 입력 및 로컬 탄약 감소 확인. 추가 서버 탄약 응답 1회 확인.
- 초기 관측 시도는 호출 순서/리스폰 시 임시 진단 객체 수명 때문에 전체 결과 자료를 남기지 못했고, 판정 근거에서 제외했다.
- 실제 음원 청취, 모든 무기·모바일 실입력, 최종 MatchOver, 관전/중도 입장, 게시본 화살표 노출은 미검증.
- 테스트 종료 후 Edit로 복귀했다. 임시 Play 진단 객체가 사라지고 원래 편집용 가이드 40개 및 cleanup 활성 상태가 유지됨을 확인했다.
- 게임 코드/템플릿/설정은 수정하지 않았다. 전체 소스·원시 진단 자료는 공개 저장소에 올리지 않는다.
