# 테니스 경기 종료 후 다시하기 불가 조사
날짜: 2026-10-16

[현재 설정](../CURRENT.md) · [종료 HUD 수정](2026-10-16-tennis-result-lock.md)

## 확인된 원인

결과 창은 재경기 버튼을 표시하지만 통합 모드 서버는 그 요청을 허용하지 않는다.

- TennisDuelClient는 MatchOver, 참가자 슬롯, 기권 여부만으로 RematchButton을 표시한다. 결과 패널은 경기 종료 8초 후 보인다. 버튼은 TennisDuelAction에 Rematch를 전송한다.
- TennisDuelService는 종료 후 8초 이상, MatchOver, 참가자 조건 외에 IntegrationManaged가 false일 때만 재경기 준비를 받는다. 현재 통합 테니스는 이 속성이 true이므로 요청이 무시되며 DuelRematchReady도 바뀌지 않는다.
- ModeTravelServer는 통합 모드를 true로 지정하며 MatchOver 후 max(ReturnSeconds, 11)초에 자동 로비 복귀를 예약한다. 현재 ReturnSeconds=8이므로 실제 기준은 11초다. 종료 신호를 놓친 경우를 위한 별도 주기 확인 경로도 복귀를 예약한다.
- 재경기 서버 처리부를 직전 HUD 수정 전 백업과 대조했으며 동일하다. 이번 HUD 차단이 새로 추가한 거절 조건은 아니다.

## 실제 재현

Studio 단일 플레이어/봇 경기에서 게임 소스를 바꾸지 않고 매 라운드 봇 체력을 0으로 만들어 실제 경기 상태를 5:0, MatchOver까지 진행했다. 테스트용 관찰값과 이벤트 연결은 Play 안에만 만들었다.

| 시점 | 관찰 |
|---|---|
| 종료 8.31초 | 결과 패널과 다시 준비 버튼 Visible/Active=true, ScreenGui Enabled=true |
| 8.31 / 9.31 / 10.31초 | 버튼과 같은 Rematch RemoteEvent 요청을 세 번 전송 |
| 각 요청 서버 수신 | MatchOver, 참가자 슬롯1, IntegrationManaged=true 확인. 준비 상태 false 유지 |
| 약 11.02초 | 로비 이동 중 상태 수신 |
| 약 11.51초 | Studio용 returnPreview 수신. 실제 텔레포트는 실행하지 않음 |
| 약 12.31초 / 서버 최종 | MatchOver 유지, 재경기 준비 false, 복귀 시작 true |

서버 요청 처리 원문을 로컬 모의 환경에서 실행한 두 경우도 확인했다. 종료 9초/정상 참가자/MatchOver 조건이 같을 때 IntegrationManaged=true는 거절, false는 준비 등록했다. 기존 처리부와 수정 후 처리부의 일치도 확인했다.

이는 버튼과 동일한 요청을 직접 보낸 검증이며 실제 마우스로 버튼을 누르거나 두 실제 계정으로 온라인 재경기를 검증한 것은 아니다. 관찰된 요청 무시와 자동 복귀의 원인은 코드와 Studio 실행에서 확인했다.

## 개선 방향 — 아직 미적용

단순히 서버의 IntegrationManaged 차단만 제거하면 이미 예약된 자동 복귀가 새 경기 중 실행될 수 있다. 다음 항목을 함께 다뤄야 한다.

1. 통합 서버에서 현재 경기 참가자의 재경기 동의를 수집한다. PvP는 양쪽 모두 동의, 봇전은 사람 참가자의 동의를 기준으로 한다. 관전자·퇴장자·이미 복귀 중인 참가자는 제외한다.
2. 재경기 결정과 자동 복귀가 경쟁하지 않도록 경기별 예약 식별자로 종료 신호/주기 확인 양쪽의 이전 복귀 예약을 무효화한다. 다음 경기가 끝나면 새 예약을 생성하도록 상태도 초기화한다.
3. 점수·준비 상태·결과 카메라/HUD·기록을 새 경기 기준으로 초기화하고 기존 참가자/방 상태와 일치시킨다.
4. 결과 화면에 상대 준비 여부와 대기/복귀 상태를 표시한다. 재경기를 실제 지원하지 않는 상태에는 작동하지 않는 버튼을 표시하지 않는다.

이번 요청은 조사이므로 게임 편집본과 설정은 변경하지 않았다. 조사 종료 후 Play를 정지했고 읽은 핵심 4개 소스가 조사 전과 같은지 대조했다. Roblox 게시도 수행하지 않았다. 원시 관찰 자료와 테스트/소스 사본은 로컬에만 보관한다.
