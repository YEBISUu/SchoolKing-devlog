# 2026-10-11 스나이퍼 명중음 보완

[현재 설정](../CURRENT.md) · [버그](../BUGS.md)

## 사용자 요청과 확인

스나이퍼로 맞혔을 때 다른 총에서 나는 ‘띵’ 명중음이 들리지 않는다는 요청이다. 사용자는 처치음이 아니라 맞힐 때마다 나는 명중음이라고 확인했다.

수정 전 스나이퍼 발사 → ShieldSystem → HitSoundEvent 경로를 확인했다. 테니스 Play의 임시 대상에 대한 스나이퍼 피해75와 shield_hit / shield_crack / hp_hit 수신, Sound 생성·로드·재생 상태를 관찰했다. 따라서 모든 스나이퍼 타격에서 이벤트가 누락된다고 재현된 것은 아니다.

확인된 누락은 실드 파괴 분기다. shield_crack은 환호만 재생하고 일반 명중음을 생략했다. 환호가 이미 재생 중이면 해당 분기 전체가 반환된다. 높은 단발 피해의 스나이퍼에도 일반 명중 피드백을 주도록 변경했다. 발사·볼트음에 가려지는 가능성은 별도 음량 균형으로 보완했으며, 최초 증상의 단일 원인이라고 확정하지 않는다.

## 적용과 설정

TGS·테니스 Studio 편집본에 다음 두 소스를 수정했다.

- ServerScriptService.ShieldSystem: 기존 명중음 이벤트의 두 번째 인자로 공격 시 장착 무기 이름 전달. 피해·실드·통계 계산 및 원래 소리 종류 유지.
- StarterPlayer.StarterPlayerScripts.HitSounds: 스나이퍼만 명중음 우선 처리.

| 항목 | 최종 값 |
|---|---|
| 실드 명중 | 기존 shield_hit, rbxassetid://109030488133733 |
| 체력 명중 | 기존 hp_hit, rbxassetid://71262762119856 |
| 스나이퍼 명중음 | 템플릿 볼륨과0.9 중 큰 값, 한 번 재생 |
| 실드 파괴 | shield_hit + 기존 환호1회 |
| 환호 중 재명중 | 명중음 재생, 환호 중복 시작은 차단 |
| 동시에 관통한 여러 명중 | 0.035초 내 짧은 명중음1회 |
| 로컬 발사/볼트음 | 명중 뒤0.22초 동안 기존 볼륨의35%, 이후0.12초에 원래 볼륨으로 복원 |

감쇠는 PlayerGui의 Sniper Fire/BoltAction과 이름·SoundId가 모두 일치하는 소리에만 적용한다. 명중 후 잠깐 늦게 생성되는 볼트음도 같은 감쇠 구간을 사용한다. 상대가 듣는3D 발사음, 재장전음, 다른 총의 명중 볼륨은 변경하지 않았다. 게임의 피해량·탄약·관통·반동·배율도 변경하지 않았다.

## 실제 수행한 검증

- 양쪽 원본을 Studio ServerStorage와 로컬 outputs에 백업 후 변경.
- 두 소스씩 컴파일 통과. Play 종료 후 양쪽 Edit 소스가 최종 준비본과 같음을 확인.
- 테니스 Play에서 일반 LocalScript와 임시 서버 RemoteEvent로 실제 HitSounds 콜백을 실행하여16개 검사 통과.
- 실드/체력 명중1회, 최소 볼륨0.9, 음원 IsLoaded/IsPlaying 확인.
- 발사음 감쇠, 늦게 생성된 볼트음 감쇠, 복원 중 재명중 이후 원래 볼륨 복원 확인.
- 실드 파괴 시 명중음+환호, 환호 중 추가 명중음 및 환호 중복 차단 확인.
- 동시 관통 이벤트의 중첩 억제, 다른 총의 기존 볼륨/파괴음 유지, 무기 인자 없는 기존 이벤트 호환, 잘못된 소리 이름 무시 확인.
- 첫 시험의0.9 비교 실패는 Sound.Volume의 부동소수점 저장값0.899999976으로 인한 테스트 문제였다. 허용오차 비교로 수정한 검사가 통과했다.

실제 사람이 듣는 ‘띵’의 선명도와 게시된 온라인 다인전은 미확인이다. 위 Play 검사는 임시 이벤트를 주입한 소리 경로 검증이며, 최종 코드의 전체 다인 사격 검증과 구분한다. 시험용 Script/RemoteEvent/표적은 Play 종료로 제거했으며 Edit에는 남기지 않았다.

## 복구와 공개 범위

양쪽 ServerStorage.SniperHitSoundBackup_20261011에 원본 HitSounds/ShieldSystem 및 RollbackCommand를 보관했다. Play를 중지한 Edit에서 복구 명령을 실행하면 두 원본 소스를 되돌린다. 이번 작업에서는 복구 명령 자체를 실제 실행하지 않았다. 로컬 outputs에도 원본·최종본·시험 자료를 보관했다.

Roblox 게시하지 않았다. 공개 GitHub에는 개발 문서만 반영하며 게임 소스·원시 로그·플레이스 백업은 포함하지 않는다.
